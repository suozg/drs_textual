# DRS Textual

**DRS Textual** — термінальна версія Document Retrieval System для імпорту, зберігання та пошуку документів у зашифрованих базах даних SQLCipher.

Інтерфейс побудований на [Textual](https://textual.textualize.io/) і працює в терміналі. Проєкт містить пошук документів, пакетний імпорт файлів, SQL-інтерфейс, керування базами даних і налаштування.

Репозиторій: <https://github.com/suozg/drs_textual>

## Можливості

### Пошук документів

- Повнотекстовий пошук за вмістом документів.
- Пошук за назвою файлу.
- Фільтрація за початковою та кінцевою датами.
- Перегляд тексту вибраного документа.
- Пошук слова або фрази всередині відкритого документа з переходом між збігами.
- Відображення результатів із зазначенням бази даних, у якій знайдено документ.
- Видалення вибраного документа з підтвердженням.

Кнопка `∞` показує документи за вибраний діапазон дат без текстового запиту.

### Імпорт документів

Програма сканує вказану папку та її підкаталоги й обробляє файли:

- `.doc`
- `.docx`
- `.rtf`

Під час імпорту програма витягує текст, нормалізує апострофи, визначає дату документа за назвою файлу або структурою шляху та записує документ у вибрану базу даних.

Якщо файл із такою назвою вже є в базі, програма порівнює хеш вмісту й оновлює запис, коли вміст змінився. Незмінені документи пропускаються. Під час сканування можна запросити зупинку обробки.

### SQL-інтерфейс

- Вибір бази даних.
- Виконання SQL-запитів.
- Перегляд результатів у таблиці.
- Побудова плану виконання через `EXPLAIN QUERY PLAN`.
- Експорт результатів у CSV.
- Очищення редактора запитів.

SQL-інтерфейс дозволяє виконувати не лише запити читання, а й команди зміни даних. Перед виконанням `UPDATE`, `DELETE`, `DROP` та інших змінювальних команд переконайтеся, що вибрано правильну базу даних і є резервна копія.

### Бази даних і безпека

- Бази даних зберігаються у форматі SQLCipher — зашифрованому форматі SQLite.
- Майстер-пароль захищає базу налаштувань, у якій зберігається реєстр робочих баз.
- Можна створити нову базу даних або підключити наявну.
- Програма перевіряє пароль під час підключення до бази.

Майстер-пароль і пароль робочої бази — різні поняття. Зберігайте паролі в безпечному місці. Втрата пароля до зашифрованої бази може зробити її вміст недоступним.

## Вкладки та клавіші

| Клавіша | Дія |
| --- | --- |
| `F1` | Пошук |
| `F2` | Імпорт |
| `F3` | SQL |
| `F4` | Налаштування |
| `F5` | Про програму |
| `F6` | Перемкнути світлу/темну тему |
| `Ctrl+Q` | Вийти з програми |

У списку результатів пошуку також доступні клавіші `j` / `k` для переходу між записами.
У вікні документа доступні клавіші `v` / `h` / `j` / `k` / `l` для виділення тексту та `y` для його копіювання в буфер обміну. 

## Вимоги

Для запуску з вихідного коду потрібні:

- Python 3.11 або сумісна версія Python, підтримувана встановленими залежностями.
- SQLCipher через пакет `sqlcipher3-wheels`.
- LibreOffice для витягування тексту з `.doc` і `.rtf` (команда `libreoffice` має бути доступною через `PATH`).
- Термінал із підтримкою інтерфейсу Textual.

Файли `.docx` читаються за допомогою `python-docx`. Для `.doc` і `.rtf` програма запускає LibreOffice у headless-режимі. Якщо LibreOffice відсутній або не запускається, витягування тексту з цих форматів не спрацює.

## Запуск із вихідного коду

Клонуйте репозиторій:

```bash
git clone https://github.com/suozg/drs_textual.git
cd drs_textual
```

Створіть віртуальне середовище та активуйте його.

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

**Windows PowerShell:**

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
```

Встановіть Python-залежності:

```bash
python -m pip install --upgrade pip setuptools wheel
python -m pip install textual sqlcipher3-wheels python-docx requests pyperclip
```

Запустіть програму з кореня репозиторію:

```bash
python main_frame.py
```

Файл `styles.tcss` має залишатися доступним програмі. Якщо запускаєте програму з вихідного коду, не переміщуйте його окремо від проєкту.

### LibreOffice

У Linux, macOS або Windows встановіть LibreOffice і переконайтеся, що команда `libreoffice` доступна з термінала:

```bash
libreoffice --version
```

Якщо ця команда не знаходиться, додайте каталог виконуваного файла LibreOffice до `PATH` або налаштуйте виклик LibreOffice у `utils.py` для своєї системи.

## Збірка виконуваного файла

У репозиторії можна використовувати PyInstaller для створення окремого виконуваного файла. Приклад команди для Linux/macOS:

```bash
python -m pip install pyinstaller
pyinstaller --clean --noconfirm --onefile \
  --name drs_textual \
  --collect-submodules textual \
  --hidden-import=pyperclip \
  --add-data "styles.tcss:." \
  main_frame.py
```

У Windows роздільник у параметрі `--add-data` інший:

```powershell
pyinstaller --clean --noconfirm --onefile `
  --name drs_textual `
  --collect-submodules textual `
  --hidden-import=pyperclip `
  --add-data "styles.tcss;." `
  main_frame.py
```

Готовий файл буде створено в каталозі `dist/`.

Виконувані файли потрібно збирати окремо для цільової операційної системи й архітектури процесора. Збірка для Linux не є виконуваним файлом для Windows або macOS. Після збірки перевірте запуск на цільовій системі, зокрема роботу SQLCipher, імпорту документів і доступність LibreOffice там, де він потрібен.

## Де зберігаються налаштування

Програма створює каталог конфігурації `drs` у стандартному каталозі налаштувань користувача:

- Linux: зазвичай `~/.config/drs/`, якщо не задано `XDG_CONFIG_HOME`.
- macOS: зазвичай `~/.config/drs/`, якщо не задано `XDG_CONFIG_HOME`.
- Windows: у каталозі, заданому `APPDATA`.

Файл бази налаштувань у поточній версії називається `settings.db`. Не видаляйте його, якщо потрібно зберегти реєстр підключених баз даних.

Робочі бази зберігаються за шляхами, вказаними під час створення або підключення. Перед перенесенням програми на інший комп’ютер скопіюйте потрібні бази даних і переконайтеся, що шляхи до них доступні.

## Важливі зауваження

- Перед імпортом великої кількості документів створіть резервну копію бази даних.
- Перевіряйте вибрану базу перед видаленням документів або виконанням SQL-команд, що змінюють дані.
- Імпорт `.doc` і `.rtf` залежить від зовнішнього процесу LibreOffice.
- Для поширення зібраних виконуваних файлів перевіряйте їх на кожній цільовій ОС; збірка сама по собі не гарантує, що всі зовнішні програми та шляхи доступні.
- Не зберігайте робочі бази в тимчасових каталогах або в місцях, які автоматично очищуються.
